# CaeRice theming architecture

CaeRice does not hard-code an independent palette per module. The shell, custom QML and external applications derive from the same active Caelestia scheme.

## 1. Inventory before mutation

`scripts/features/install-theme-dock.py` always inventories the machine **before** installing or changing any scheme file.

It compares the installed Caelestia scheme directory with current upstream CLI data, creates a full recovery snapshot under:

`~/.local/share/caelestia-custom-system/snapshots/theme-dock-<timestamp>/schemes-before`

and copies locally added/modified scheme files into:

`caelestia/schemes/local-preserved/latest/`

with an `inventory.json` manifest. Existing scheme paths are never overwritten by the installer.

This matters because current Caelestia CLI resolves named schemes directly from its packaged `caelestia/data/schemes` directory. CaeRice therefore treats that directory as a compatibility install target, while the durable source of truth is this repository.

## 2. Scheme catalog

The installer fills in any scheme files present in the current official `caelestia-dots/cli` catalog that are missing locally, without replacing installed files.

CaeRice also provides an additional dark scheme pack. Current additions include:

- `kanagawa/wave`
- `kanagawa/dragon`
- `oxocarbon/default`
- `cyberdream/default`
- `ayu/mirage`
- `nightfox/default`
- `material-ocean/default`
- `github/dark`
- `horizon/default`
- `monokai-pro/default`
- `poimandres/default`
- `aura/default`
- `flexoki/dark`
- `melange/default`
- `vague/default`
- `bamboo/default`
- `onix/onix`

The palette-based schemes are generated by `scripts/features/generate-caerice-schemes.py` into the full role set expected by Caelestia: Material surface roles, semantic colours, terminal colours and compatibility aliases. `onix/onix` is vendored separately from the upstream Caelestia CLI proposal so its authored role mapping is retained.

## 3. Shell visual contract

Custom CaeRice QML uses the same services as native Caelestia:

- `Colours.palette.*` for opaque Material roles.
- `Colours.tPalette.*` only when inheriting the user's shell transparency is intentional.
- `Tokens.*` for spacing, padding, rounding, typography and animation.
- `import qs.services` whenever `Colours` is referenced.
- `import Caelestia.Config` whenever `Tokens` is referenced.

Avoid fixed RGB/hex colours in normal UI components. Fixed colours are acceptable only for semantic content that must not follow the active theme.

## 4. Global shell shape

Use `~/.config/caelestia/shell.json` for supported appearance scales. Use `shell-tokens.json` only for a small curated CaeRice token overlay; it is an advanced upstream interface and should not be copied wholesale.

Dock, Launcher, Clipboard, Overview and future CaeRice panels should share the same surface hierarchy, corner radii, spacing rhythm, typography hierarchy, animation language and active/hover/selected semantics.

## 5. External application bridge

`install-theme-dock.py` merges theme targets into `~/.config/caelestia/cli.json`. Core terminal/Hypr/GTK/Qt integration is enabled, and integrations such as Chromium/Brave, Spicetify, btop/nvtop/htop, Cava, Fuzzel, Discord-family clients and Zed are enabled when the corresponding programs are found.

Kitty uses a Caelestia user template rather than a standalone hard-coded palette:

`~/.config/caelestia/templates/kitty-caerice.conf`

which Caelestia renders to:

`~/.local/state/caelestia/theme/kitty-caerice.conf`

and `kitty.conf` includes that generated file.

## 6. Dock favourites

CaeRice Dock uses `GlobalConfig.launcher.favouriteApps`, the same source as the launcher. A favourite is rendered even when it has zero windows; running apps that are not favourites are appended afterwards.

The installer preserves existing favourites and, when installed, seeds exact DesktopEntry IDs for common primary apps (Kitty, Dolphin, Brave, Spotify, GitHub Desktop and Claude). It also adds a visible pin control to Dock items, while right-click remains a secondary pin/unpin gesture.

There is no second favourites database. Launcher and Dock stay synchronized through `favouriteApps`.
